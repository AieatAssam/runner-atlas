Methods and caveats

What is measured

Each sample is one run of a fixed benchmark set on a GitHub-hosted runner, with its label, CPU family, operating system, region and timing fields. Units are stated beside each figure.

What cannot be known

Noisy neighbours on macOS and Windows, virtualised CPU topology, hypervisor preemption and page-cache effects all shift results and are not separated out. Network figures measure transfers to GitHub only. The network throughput index is a 1 MiB short transfer, so it is bounded by slow start and round-trip time rather than link bandwidth.

Where region comes from

Region comes from instance metadata where available, otherwise from a curated address-range table matched against the runner’s egress address, which is held in memory for the match and then dropped. GitHub’s published address ranges confirm the runner belongs to the Actions pool but carry no region. Stored records never contain IP addresses.

Sampling bias

Every sweep starts at 17 minutes past the hour, so other minutes go unobserved. Scheduled runs that were dropped are invisible except as missed slots.

Why steal is only a proxy

CPU steal shows time a virtual CPU waited for the host. It correlates with slow runs but does not measure the neighbour directly.

Statistics

The run is the unit of analysis. Intervals come from a cluster bootstrap over runs with 1000 resamples. Confidence tiers depend on the number of survey days, the sample count and whether the best and worst slots are separated. Change points use a penalised search over daily medians. A slot’s wait score is its median start delay plus half the gap between that median and the 90th percentile, so a slot with rare long waits ranks lower.

Privacy

The collector records hardware, operating system, region and timing only. It keeps no user data, repository names or workflow content.

Data downloads
